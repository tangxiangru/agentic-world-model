## 2. Recipe decisions and reasoning

**Plan at minute 1.** TaskCreate at 12:26:45: "Rejection sampling / STaR round — Generate multiple CoT samples on GSM8K train with SFT model, filter correct, retrain" (L1215–L1216 A20). GRPO/RL is never mentioned in the trace; there is no on-policy RL code. No sentence weighs RFT against RL, budget, or risk — the pipeline was decided before the baseline finished.

**Data.** sft1: GSM8K train ×2 + 30k MetaMath GSM (44,946 examples; the human CoT keeps GSM8K's terse style). Auxiliary prompts for RFT: OMI-2 `augmented_gsm8k` **questions with expected_answer** as verifier (73k unique). Every mix was decon-checked (`runs/decon_*.txt`, all 0). **Few-shot prefix.** `fewshot_prob 0.15`, k∈[1,10] shots sampled from the first 3,000 GSM8K-train rows (`build_fewshot_pool`), rendered as system message — the harness's exact 10-shot block was reproduced (L1711) but only used for the token-count check, not mixed into training. RFT prompts carry no few-shot block.

**SFT hyper-parameters** (L2643 A64; identical for sft2/sft3): full FT, vision tower/projector frozen, fp32 weights + bf16 autocast, **sdpa attention (no flash-attn)**, `adamw_bnb_8bit`, Liger, grad ckpt, bs 16 × accum 8 = 128, lr 1.2e-5 cosine (warmup 3%), 1 epoch, max_len 2560, `adam_beta2 0.95`. Every round retrains **from the frozen base** on the new mix ("always retraining from the frozen base snapshot", L8220 final message) — so each RFT round costs a full 65-min SFT, not a short continuation.

**RFT settings.** Round 1 final: k=6, T=0.9, top_p 0.95, max_tokens 320, ≤4 kept per question after dedupe by number-skeleton, `finish_reason == "stop"` required (gen_rft.py). Round 2: k=5, T=0.95 from sft2.

## 5. Pitfalls

Losses ≥ 0.1 h:
- **RFT generation with zero yield, 13:37 → 15:44 (2.1 h).** Three phases: (a) 13:37–13:58 two restarts for throughput ("CPU-bound (54% GPU util)", L3709; `VLLM::EngineCore` at 100% CPU, L3889); (b) 13:58–15:13 a 75-minute run whose post-processing printed `pass rate 0/117365 = 0.000` (L4448) because no sample had `finish_reason == "stop"`; (c) 15:13–15:44 diagnosis: first the double-BOS hypothesis (L4736, a real bug but not the cause), then `dbg_gen.py` showed the stop works with n=1, then reading `vllm/v1/engine/llm_engine.py` + `parallel_sampling.py` (L5632 A193) gave the cause: child requests of an n>1 parent are fanned out from the pre-`update_from_generation_config` params, so `<end_of_turn>` is not a stop token. Fix: `stop_token_ids=[eot]` (L5787 A197). The scientist's own accounting: "A vLLM bug cost ~2 hours." (final message).
- **sft1 killed by the 120 s tool timeout, 12:38–12:44 (0.1 h)**: `nohup python train_sft.py … &` followed by `sleep 120` in the same foreground call; "Command timed out after 2m 0s" (L2660) and the GPU read 0 MiB at 12:43:47 (L2779). Relaunched with `setsid nohup … < /dev/null & disown` (L2796), and every later launch used that form.
- Corrupt `.pyc` crashed the sft2 eval, 17:50–17:56 (0.1 h): scanned all `__pycache__/*.pyc` with `marshal.loads`, removed the one bad file (L6657 A232).
- Smoke-test OOM at 12:33 (~0.05 h); sft2 first launch "Exit code 144" at 16:35:48 (0.01 h).

Traps avoided by prior knowledge:
- `p_enc = tok(prompts, add_special_tokens=False)` in `SFTData` (train_sft.py, 12:31) — no double BOS in **training**; the same trap was walked into in **generation** (`LLM.generate` on template strings) and fixed at 15:17.
- Vision tower/projector frozen; Liger; 8-bit Adam; fp32 weights — in the first script version.
- Target ends with `<end_of_turn>\n` so the model learns to stop (the base model's 6% "is a formatting artifact: it never emits a stop token", README).
- MetaMath answers re-verified against GSM8K-train gold before use (`prepare_data.py`: "metamath gsm kept=… wrong=…").
- `finish_reason != "stop"` filter and skeleton dedupe in RFT; `.raw.jsonl` dump then chunked incremental output so a crash cannot lose 75 minutes again (L5265 A182).
- `verify_final.py` loads `final_model` with stock transformers ("no liger-kernel, which was training-only") — checks the artifact outside the training environment.

## 7. Verdict

Largest contributors to the score (and to it being the lowest clean control):
1. **Data/recipe ceiling.** SFT on GSM8K-train human CoT + MetaMath gave 59% where OMI-2-based SFT gave 70–75% in the other cells; one RFT round recovered to 73% greedy, a second round regressed (sft3 67.6 vs sft2 70.8 at n=500) and the soup added only +0.4/+1.0. No on-policy RL was ever attempted (c00r06's GRPO added +5 on the same base recipe scale).
2. **2.1 h lost to the vLLM n>1 stop bug** (13:37→15:44) plus 0.3 h of restarts — the third training round (sft3) started at 18:57 instead of ~16:45, which removed any chance of a GRPO stage or a third RFT round.
3. **Greedy decoding applied late but shipped**: +7 pts on sft2; it is the single biggest measured gain in this cell and it was available at 12:30.

Knowledge worth a rule in the protocol arm's pitfalls list:
- "With vLLM offline generation and `n>1`, the `<end_of_turn>` stop id from `generation_config.json` is dropped for child requests: pass `stop_token_ids=[1, 106]` in `SamplingParams`, and pass `TokensPrompt(prompt_token_ids=tok(text, add_special_tokens=False))` rather than a chat-template string (which gets a second `<bos>`). Symptom: 0% pass rate at n>1 while n=1 works." (L4448 → L5752; 2.1 h)
- "Launch every long job as `setsid nohup … > log 2>&1 < /dev/null & disown` in its own Bash call; a `nohup … &` sharing a call with a `sleep` is killed when the 120 s tool timeout fires." (L2660 → L2796)
- "When the base `generation_config.json` says `do_sample: true`, rewrite it to greedy on the first checkpoint and measure the delta before planning further rounds; the delta here was +7 points and was measured 5.5 h after being seen." (L1711 vs L6812)
