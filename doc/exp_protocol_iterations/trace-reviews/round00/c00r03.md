Knowledge to transfer (exact sentences for a pitfalls list):
- "A full 1319-item `evaluate.py` run takes about 4 minutes at `--max-connections 32 --gpu-memory-utilization 0.85 --max-tokens 1024`; never pick between checkpoints on `--limit 200` — its ±3-point noise is larger than any real difference you will see, and it made a +1.0 RFT gain look like +4."
- "vLLM's offline `LLM.generate` stops only on `<eos>`(1), not on `<end_of_turn>`(106): pass `SamplingParams(stop_token_ids=[1, 106])` in every rejection-sampling or self-eval script, and print `finish_reason` on a 16-prompt probe before launching an hour-long generation (this cell read a 6% pass rate that was really 96% and lost 1.4 h)."
- "Never `--init` a training run from a directory whose `generation_config.json` was patched to greedy (`do_sample=false` with `temperature=0.0`/`top_k=0`): HF validates the config inside `save_pretrained` at the end of training and raises 'Fix these issues to save the configuration', losing the run (0.75 h here). Patch greedy only on a packaged copy, or set `model.generation_config` to a valid sampling config before saving."
- "`pkill -f <script>` leaves vLLM's `EngineCore` child alive holding the GPU; kill the PIDs listed by `nvidia-smi --query-compute-apps=pid` before relaunching."
