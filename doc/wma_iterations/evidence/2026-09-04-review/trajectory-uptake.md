## 改进优先级与可检验指标

1. **风险转成能改动作的前提。** 对格式干预，先明确真实 grader 提示下早期 checkpoint 该达到的 stop/ANSWER 门槛，未过则修复而非完整跑完再解释。对“新数据”要求问题级 novelty 与 solution-level novelty 分开；w06r02 两个相反案例直接支撑它。主指标：审查后实际 proposal change / unrun / early-fix，按 request ID 留痕；不能只算 L3 字面答案。
2. **选择质量优先于无差别重复短评。** 两臂统一有效 decoder/模板/样本 ID；N150 只做筛选，出现可颠倒最终提交的近分时，用按本 run 实测吞吐定价的更大共同集合。另设有需要才做的同集合重复估计运行变异。主指标：是否避免后来大集合反转、选中模型是否保持胜率、eval 成本；不要把用于选模的 test p 值做独立泛化证据。
3. **checkpoint 形成完整履约。** 明确保存步、保留数、可加载的 tokenizer/config、要评的短名单、是否真的读取、最终选择。D 能改保存但末段仍转去未经单独验证的 soup；已有 w10 同类缺陷。主指标从“提到了 save_steps”改为“至少两个已保留 checkpoint 在同一尺上真正被比较”。新增设计须与已排队 D/H 区分，避免重复候选。
4. **把首轮训练 recipe 作为独立科学轴。** 固定数据 source/去重/提示组成和计算预算，分别测试 token throughput、问题覆盖与训练长度，保留检查点。C 的14.63 pp极差与约2×吞吐差值得受控实验；不是据两条轨迹直接推广“数据越多越好”。w08r04 训练后段、w10r02 多一个 epoch 的相反结果说明不能定死终点。
5. **报告与测量分开记录预测、修复、选择。** append-only 留每轮 verdict 与 proposal hash；分 final held-out score、card 中间分、机制诊断。零 leak gate 仍由根代理 ledger 执行，以上观察不为 A–D 推广背书。建议保留真实 action examples，不用 uptake.py 的宽松正则推断因果。
