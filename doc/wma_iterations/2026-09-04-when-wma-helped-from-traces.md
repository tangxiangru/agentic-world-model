**WMA 什么时候实际有用：按原始轨迹逐事件归因**

本报告回应“从 traj 看什么时候 WMA 有用”。只采用此前冻结的完成 cell，重新读取裁决前的原计划、代码/产物、WMA 返回、scientist 后续真实动作和结果。没有以设计目标、理论用途、建议措辞或终稿的自我归因代替行动证据。这是针对性案例审计，不据此估计全体建议的有效率。

目前最扎实的共同点是：scientist 已有具体方案，却误以为关键前提或实现已经正确；WMA 找到一个可核对的不一致，随后 scientist 真正修改了代码、数据、候选或选择规则。具体作用大小必须逐条分开：修复执行、纠正依据、补充候选、改变选模，以及最终分数提升，不是同一件事。

**最强的三条完整链**

`w08r03/exp-03`：18:55 scientist 已选 greedy → 19:00:42 WMA 展示实际参数解析差异 → 19:00:48 scientist 说“caught a real defect” → 19:00:52 改脚本 → 19:06:44 评估 → 19:08:38 exit0、65.33%、150/150正常停止。这里的WMA贡献不是想出greedy，而是让真实执行符合已有意图；+10pp是 corrected-greedy 对 sampled 的观测差，不是随机有无WMA效应。

`w06r02/exp-06`：18:19 写下26k unseen problems的训练计划 → 18:26 WMA指出25,965问题已见 → scientist明确说reviewer指出的是second solutions → 新建问题级过滤脚本 → 18:33实际只得到56条 → 18:34关闭unrun卡。这里确认了计划因新事实而改变。此前scientist已经知道第二解与新问题的区别，WMA纠正的是该次计划前后不一致。

**同一份裁决里，并不是每条建议都有用**

- `w06r02/exp-06` 的数据重合事实改变了计划，但同份要求评旧checkpoint-200的建议没有执行，后来明确被拒绝，理由是预期约25分钟，不如做hard-example mining。
- `w07r02/exp-02` 的calculator注释修复被执行，但“边训第二epoch边评第一epoch”被scientist以显存冲突拒绝；只训一个epoch的建议也没有采用。greedy脚本在这次裁决前已经写好，不能把后来的greedy评估归给本次建议。
- `w09r01/exp-05` 的保存间隔1080→540确实改了，但23:09已看到中期点后，实际命令是sleep1900等训练完，没有做建议的中途评估/早停。之后拿这些点做了soup，但77.4%低于final79.0%。这里有参数采纳，没有证明checkpoint选模或节省训练时间。
- `w08r02/exp-04` 的WMA建议删除4887条疑似标签错的orca行。scientist按建议抽查14条，发现14条均正确，并实际拒绝过滤；“答案数字也出现在题目”不能作为这批数据应删除的充分证据。发生了额外核查，未发生删除或可确认损害。
- `w06r02/exp-03` 的WMA已指出0-shot训练与10-shot评测不一致，但只安排训练后诊断，仍预测+32到+68pp。1.35h后正式分仍6%。此处有正确风险描述，却没有及时改变导致失败的条件；不能把“指出过风险”计为解决问题。

**两条额外核对，避免高估贡献**

`w06r01/exp-05` 的第一次训练在保存处失败。20:37 scientist独立诊断并完成补丁；20:43已经重启时才读到WMA要求先做保存smoke，随后停止并用2步/每步保存进行验证，exit0后再启动。WMA促成的是补丁验证，原始诊断与补丁不是它做的。没有证据显示补丁仍错，因此不能把验证说成又避免了一次必然失败。

`w07r01/exp-06` 的scientist确实执行了WMA要求的ingredient单独dev300评价和错误重合检查（74%、42共同失败），然后做三路soup。但n500只高0.4pp、paired p=.9007，scientist仍说“null但两把尺都不差”并提交。这个例子只能支持检查被执行，不能支持WMA成功约束最终近分选择。新增原始摘录保存在 [补充片段](/home/robtang_google_com/gangda_workspace/agentic-world-model/doc/wma_iterations/evidence/2026-09-04-review/empirical-root-excerpts.json)。

**从这些轨迹归纳的“什么时候”**

1. **准备启动时，计划描述与实际代码/文件不一致。**三次独立修复分别纠正“写do_sample就greedy”“打印packaged就有权重”“源keys相同就可load”；有明确新证据、即时响应和成功执行。
2. **准备花下一段预算时，本轮计划漏掉了自己早已知道的条件。**26k问题重合数使scientist放弃“新问题”训练；泛泛提醒问题多样性本身并不是新贡献。
3. **已有候选、正要挑选或合并时，WMA补了一个具体选项或具体比较。**两路checkpoint组合真正进入评估；full共同集合真正改变模型选择。仅仅复述已计划的soup、配对统计或更大N不重复记功。
4. **一个建议被落实到下一步动作，才看到作用。**同cell既有完整采纳，也有拒绝、已自行计划、只改记录未执行；不能把verdict或cell整块标成“有用”。

这些结论来自已发生的事件。最清楚的收益是纠正错误确信、修复真实实现、增加局部候选与改变一次选择；没有据这些案例声称整体最终分数稳定改善，也没有把未运行方案的计划时长记成已量得的净GPU节约。
