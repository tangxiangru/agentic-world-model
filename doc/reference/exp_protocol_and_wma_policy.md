# 实验规程(exp_protocol)与世界模型策略(WMA policy):定义与分界

**用途**:长期有效的角色定义。一个 agent(scientist)在预算内做模型训练实验时,有两类东西在辅助它——实验规程与世界模型策略。本文定义这两者各自是什么、不是什么、以什么标准划界。后续两条线的研发以此为准。生命周期、契约格式、字段级细节不在本文范围。

**日期**:2026-09-01 **状态**:生效

---

## 一、为什么拆成两条线

scientist 做实验时,起作用的知识分两类:

- **怎么把一个实验做对**:先写假设再跑、比较对象必须同协议、eos 配错分数归零、数据版本要 pin。这类知识是**确定性的**——做对了就是对了,不依赖判断,而且**每一步都在起作用**。
- **该做哪个实验**:这个方向值不值得试、先试哪个、大概会怎样、有没有更好的方案。这类知识是**不确定的**——判断了也未必对,而且价值**集中在开题时刻**。

两类知识混在一个角色里会互相拖累:判断者被拉去做 checklist,浪费昂贵的推理;规程被塞进判断的不确定性,本来能 100% 执行的纪律变成"建议"。拆开之后,前者可以机械化、可以在 CPU 上测试、可以从历史里挖掘沉淀;后者可以专注于判断,并被单独评估。

## 二、判定规则

> **能写成 checklist、lint、schema 或脚本的,归实验规程;需要在不确定性下权衡的,归世界模型策略。**

所有灰色地带用这条规则判。四个例子把边界钉死:

| 事项 | 归属 | 理由 |
|---|---|---|
| "eos token 必须与 template 一致,否则模型不出停止符" | 规程 | 确定性,可写成训练前检查 |
| experiment card 的 schema 与校验 | 规程 | 是格式,不是判断 |
| 维护卡链与 checkpoint 的谱系索引 / 选择从哪个起始点继续 | 规程 / 策略 | 提供可查询的索引是规程;选哪个是判断 |
| "这个方向三个先例全部失败,不值得再试" | 策略 | 先例能查,"不值得"是权衡 |

## 三、实验规程(exp_protocol)

### 定义

scientist 做实验时必须遵守的工程纪律、实验记录的标准,以及支撑二者的薄工具。它回答的是"怎么做对",不回答"做什么"。

### 职责

1. **纪律**。假设、设置、评估方式先于结果存在;比较对象在同一协议下测量;先于结果写下的部分不可事后修改;失败和中止的实验同样留下记录。
2. **记录**。每个实验一张 experiment card:问题、假设、设置、评估、结果、结论,**以及处境**——剩余预算、已排除的备选、触发这次实验的观察、之前踩过的坑。处境是本规程与常见"论文格式"记录的关键区别:保真的对象是决策发生时的状态,不只是动作和结论。
3. **理解实验**。card 与谱系索引要让另一个读者——失忆后的 scientist、同任务的另一个 agent、事后的人——只凭记录回答三个问题:在验证什么、怎么重跑、当时处于什么处境。
4. **谱系与起始点**。每张 card 记录父 checkpoint,卡链可回溯到 base model;我们自己跑的 run 按规程保存 checkpoint,使后续探索能从任意历史节点续跑。历史语料中的 run 没有 checkpoint,起始点只能是配方级的重跑,规程需如实标注。
5. **常见坑**。环境特有的过程知识(eos/template/prompt 一致性、数据集版本、评估脚本路径、沙箱内不可达的文件等)沉淀为训练前检查与 checklist。**能机械化的必须机械化**——一条写进 pre-flight 脚本的坑,执行率是 100%,成本是零。

### 产出形态

- 一份给 scientist 读的 skill(`skills/exp_protocol/`,跨 Claude Code 与 Codex 共用);
- experiment card 的 schema;
- 薄工具:card 校验、pre-flight 检查、谱系索引查询。

明确不含:状态机、会挂起训练等待回复的协议、需要 LLM 才能执行的规则。规程的全部机制必须能在 CPU 上端到端测试。

### 不做什么

不判断实验值不值得做,不预测结果,不生成方案,不替 scientist 做决定。规程只保证"做了就做对、做了就留痕"。

> 注:experiment card 内有一个 `evaluation.protocol` 字段,指某次评估的具体方法(评估集、样本数、种子)。它是 card 的一个字段,与本文的 exp_protocol(整条规程线)是不同层次的东西。

## 四、世界模型策略(WMA policy)

### 定义

在不确定性下做科研判断的角色。面对当前处境、历史经验与候选方案,判断什么值得试、什么不值、先试什么、大概会怎样,并提出 scientist 没想到的方案。它回答的是"做什么",不回答"怎么做对"。

### 职责

搜索空间(什么值得试)、剔除(什么不值得,含负结果的识别与剔除)、排序(先试什么)、预判(大概会怎样)、生成(新的 proposal)。职责范围随研发迭代,不在此固定功能清单。

### 输入

**scientist 能看到的一切 context,它都能看到**:工作区、训练脚本与日志、评估输出、历史 run 的原始轨迹与 card。card 是它检索历史的索引,不是它唯一的输入——把它的视野限制在结构化摘要上会让判断失去依据。

### 衡量

主指标是 **scientist 的 GPU 小时利用率**:花在最终被采纳路径上的比例。次要指标:避免的重复实验、提前终止的无望实验。不以"预测精度"为主指标——它的价值在于让探索少走弯路,不在于报点数报得准。

### 最低要求:可对账

每次方案级判断必须留下一条结构化裁决——值得跑 / 不值得 / 建议改为 X,附一句理由——事后能与实际结果对账。只定这个要求,不定格式。没有这条,"灵活"会变成"不可证伪",判断的好坏永远说不清。

### 不做什么

不训练任何东西,不替 scientist 做决定(scientist 随时可以不听),不做规程能做的事——凡是能写成 checklist 的,不占用判断。

## 五、两者的关系

| 维度 | 实验规程 exp_protocol | 世界模型策略 WMA policy |
|---|---|---|
| 性质 | 确定性的纪律与格式 | 不确定性下的判断 |
| 回答 | 怎么做对 | 做什么 |
| 输入 | 当前实验的设置与产物 | scientist 的全部 context + 历史 |
| 输出 | 通过/不通过、card、索引 | 裁决、排序、预判、proposal |
| 执行方式 | 脚本、schema、checklist;CPU 可测 | 推理;需要模型 |
| 评估 | 执行率、card 可复现率、避免的坑 | GPU 小时利用率、裁决对账 |
| 失败模式 | 规程过重拖慢 scientist | 灵活到不可证伪;越权做规程的事 |

**知识的流向**:历史语料经挖掘产出两种东西——过程知识(坑)沉淀进规程的 checklist,结果知识(哪些方向成过、败过)成为策略的先例。规程给策略提供干净、可对账的记录与索引;策略的裁决记入 card 的处境,成为下一轮挖掘的输入。两条线通过 card 交换信息,但各自独立迭代。

## 术语

- **scientist**:在预算内做训练实验的 agent,被规程约束、被策略辅助。
- **experiment card**:一个实验的记录单元;一个问题、一个假设、一次干预、一个结果,加处境。
- **处境(situation)**:决策发生时的状态——剩余预算、已排除的备选、触发观察、踩过的坑。
- **过程知识**:环境特有的、确定性的坑与做法;归规程。
- **结果知识**:某方向在历史上成过或败过;归策略的先例。
- **pre-flight**:训练启动前自动执行的检查,过程知识的机械化形态。
